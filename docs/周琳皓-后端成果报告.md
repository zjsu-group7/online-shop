## 二、实现内容

### 1. 商品发布与管理

- 发布后商品直接进入 `ON_SALE`。
- 已存在 `ON_SALE` 或 `FROZEN` 商品时禁止再次发布。
- 名称、描述、价格按 Wiki 约束校验，价格必须大于 0 且最多两位小数。
- 图片只接受 JPG/PNG Base64，最大 5MB；未上传或保存失败时使用占位图。
- 卖家可以查看全部商品，也可以手动下架非交易中的商品。

### 2. 冻结与解冻

- 手动冻结：`ON_SALE → FROZEN`，并记录 `frozenBy = MANUAL`。
- 手动解冻：仅 `MANUAL` 冻结允许恢复 `ON_SALE`。
- 交易冻结：选择买家后记录 `frozenBy = AUTO`，不允许手动解冻。
- 商品和意向读取使用悲观写锁，实体保留 `@Version`，降低重复操作和并发状态覆盖风险。

### 3. 买家选择

接口：`POST /api/seller/products/{id}/deal`

请求：

```json
{ "intentId": 1 }
```

处理规则：

- 商品必须为 `ON_SALE`。
- 意向必须属于当前商品并处于 `WAITING`。
- 商品与意向在同一事务中分别转为 `FROZEN/AUTO` 和 `IN_TRADE`。
- 响应只返回商品快照、意向 ID 和状态，不返回口令码或口令哈希。

### 4. 交易结果

接口：`POST /api/seller/products/{id}/result`

成功 `SUCCESS`：

- 选中意向转为 `TRADED`。
- 商品转为 `OFF_SHELF`，关闭原因记为 `SOLD`。
- 同商品其余 `WAITING` 意向全部转为 `FAILED`。

失败 `FAIL`：

- 选中意向转为 `FAILED`。
- 商品恢复 `ON_SALE`。
- 其余 `WAITING` 意向保留原状态与排队顺序。
- 商品记录最近交易失败时间，供历史列表查询。

### 5. 历史记录

接口：`GET /api/seller/history`

历史范围包括：

- 交易成功下架：`historyType = SOLD`。
- 手动下架：`historyType = MANUAL`。
- 交易失败后仍恢复在售：`historyType = TRADE_FAILED`。
- 历史条目的商品字段与普通商品 DTO 保持同层，避免前端额外拆 `product` 子对象。
- `hadTradeFailure` 标记商品是否曾发生失败交易。
- 按 `closedAt` 或 `lastTradeFailedAt` 倒序返回。

### 6. 下架联动

手动下架后，商品剩余 `WAITING` 意向统一转为 `FAILED`，避免商品已经关闭但队列仍可继续处理。
