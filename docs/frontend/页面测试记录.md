## 6. 走查发现的缺陷

| 编号 | 现象 | 根因 | 修复 | 复测 |
|---|---|---|---|---|
| 1 | 商品图片上传后不显示，全部为灰色占位图 | `common.js` 的 `resolveImageUrl` 未识别 `/uploads/` 开头的完整路径，被当作纯文件名二次拼接前缀，请求 `/uploads/uploads/xxx.png` 返回 404，触发占位图兜底 | 新增 `if (String(img).charAt(0) === '/') return String(img);`（common.js L128），提交 commit：______ | A-01 / A-07 / C-05 / C-06 复测通过 ✅（浏览器实测封面正常加载） |
| 2 | 下单后商品不变「交易中」，后台没有「标记成功/失败」按钮，无法走完交易（C-10 ~ C-14） | 前端后台缺少「交易队列 + 发起交易」界面：买家下单仅排队（WAITING），须卖家选定买家发起交易（`POST /api/seller/products/{id}/deal`）商品才进入交易中；后端已有 `/api/seller/overview` 与 `/deal` 接口但页面未实现对应 UI | `admin.html` 新增「交易队列」卡片；`admin.js` 新增 `loadQueue/renderQueue`（按商品分组渲染排队买家、位次、状态）与「发起交易」按钮（调用 `Api.startTrade`）；`api.js` 新增 `startTrade(productId, intentId)`，提交 commit：______ | C-10 ~ C-14 浏览器复测全通过 ✅ |
| 3 | 多商品场景下单挂错商品：买家点击 A 商品下单，意向却挂到最新创建的在售商品上；后台队列也只展示最新商品的意向 | ① `IntentService.submit` 使用 `currentActiveProduct()` 忽略了请求中的 `productId`；② `SellerService.overview` 只返回最新一件在售商品的队列。均为迭代 1 单商品逻辑残留 | 协同后端修复：`SubmitIntentRequest` 增加 `productId`，`submit` 按 `productId` 定位商品（为空回退旧逻辑，向后兼容）；`SellerOverview` 增加 `products` 字段，`overview` 返回全部在售商品队列，提交 commit：______ | 复测通过：任意商品下单 → 后台对应商品分组出现意向 → 发起交易 → 标记结果 → 买家订单出结果 ✅ |
