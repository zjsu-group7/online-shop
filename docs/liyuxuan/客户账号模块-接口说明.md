# 客户账号模块 · 接口与实现说明

> 编写：李宇轩 ｜ 版本：v1.1（2026-10-21）｜ 对应《需求规格说明书》v3.1 FR-B4 / FR-B5 / FR-B7 / FR-B8、3.8 / 3.9
> 代码位置：`src/main/java/com/group7/shop/{entity,repository,dto,service,config,controller}`
>
> **边界约定**：本模块不修改任何他人负责的文件。意向域（华天遥）的 `Intent`、`IntentRepository`、`IntentService`、`IntentController` **零改动**；客户与下单记录的归属关系记录在本域自建的 `customer_order_links` 表。

## 一、接口清单（7 个）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/customer/register` | 否 | 注册：用户名唯一、密码加盐哈希 |
| POST | `/api/customer/login` | 否 | 登录，返回 token 与过期时间 |
| POST | `/api/customer/logout` | X-Token | 退出，token 立即失效 |
| GET | `/api/customer/me` | X-Token | 个人中心 |
| PUT | `/api/customer/me` | X-Token | 修改电话与默认交易地点（选填） |
| POST | `/api/customer/orders` | X-Token | 登录客户下单，复用意向域排队逻辑 |
| GET | `/api/customer/orders` | X-Token | 我的下单记录（仅成功 / 失败） |

统一响应体 `{ code, message, data }`，HTTP 状态码与 `code` 对齐。

## 二、接口明细

### POST /api/customer/register

请求：

```json
{ "username": "buyer01", "password": "buyer12345", "phone": "13800001111", "defaultTradePlace": "图书馆门口" }
```

响应 `data`：

```json
{ "id": 1, "username": "buyer01", "phone": "13800001111", "defaultTradePlace": "图书馆门口", "createdAt": "2026-10-21T08:00:00Z" }
```

| 情况 | 状态码 | 提示 |
|---|---|---|
| 用户名重复（忽略大小写） | 409 | 用户名已被占用 |
| 密码少于 8 位 | 400 | password: 密码不少于8位 |
| 用户名 / 电话为空 | 400 | 必填提示 |
| 默认交易地点超过 200 字 | 400 | 超长提示 |

- 响应**不包含** `passwordHash`、`salt`、`token`。
- 电话**不要求唯一**，同一电话可注册多个账号；电话不能用于登录。

### POST /api/customer/login

请求：`{ "username": "buyer01", "password": "buyer12345" }`

响应 `data`：

```json
{
  "token": "3f2a...（64 位）",
  "expiresAt": "2026-10-21T10:00:00Z",
  "customer": { "id": 1, "username": "buyer01", "phone": "13800001111", "defaultTradePlace": "图书馆门口", "createdAt": "..." }
}
```

| 情况 | 状态码 | 提示 |
|---|---|---|
| 用户不存在 / 密码错误 | 401 | 用户名或密码错误（同一文案，防枚举） |
| 连续失败 5 次 | 401 | 账号已锁定，请 N 分钟后再试 |
| 锁定期内即使密码正确 | 401 | 同上 |

- token 有效期 **2 小时**；重新登录使旧 token 失效；成功登录清零失败计数。

### POST /api/customer/logout

请求头 `X-Token`；响应 `{"code":200,"message":"已退出登录","data":null}`；旧 token 立即失效。

### GET /api/customer/me

响应 `data` 为 `CustomerView`，字段同注册返回。

### PUT /api/customer/me

```json
{ "phone": "13700003333", "defaultTradePlace": "一食堂门口" }
```

- `phone` 必填；`defaultTradePlace` 选填，传 `""` 表示清空（落库为 `null`）。

### POST /api/customer/orders（登录客户下单）

请求：

```json
{ "name": "李四", "phone": "13600004444" }
```

响应 `data`：

```json
{ "code": "K7M2QP9X", "intentId": 12 }
```

规则：

- **必须登录**（无 token → 401），这是「提交下单必须登录」的落地入口。
- 排队、口令码生成、商品在售校验全部复用 `IntentService.submit(...)`，只是额外把 `intentId` 关联到当前客户。
- 匿名下单仍可走旧接口 `POST /api/intents`（受邀基线兼容），但**不会**出现在任何客户的「我的下单记录」里。
- 商品非在售 / 姓名电话为空等情况，错误与原意向接口一致（400）。

### GET /api/customer/orders（我的下单记录）

响应 `data`：

```json
{
  "total": 2,
  "items": [
    { "intentId": 12, "productId": 3, "productName": "二手自行车", "coverImage": "/uploads/xxx.jpg",
      "submittedAt": "2026-10-20T09:00:00Z", "result": "SUCCESS", "resultAt": "2026-10-20T10:00:00Z" },
    { "intentId": 8,  "productId": 2, "productName": "台灯", "coverImage": "/placeholder.png",
      "submittedAt": "2026-10-19T09:00:00Z", "result": "FAIL", "resultAt": "2026-10-19T12:00:00Z" }
  ]
}
```

规则（对应 Q26）：

- **只返回本人**、且状态为 `TRADED` / `FAILED` 的记录；`WAITING` / `IN_TRADE` 不返回。
- 按提交时间倒序，时间相同按 id 倒序。
- 字段严格为「商品名称、下单时间、交易结果、交易时间」+ 必要的 id 与封面，**不暴露其他买家信息**。
- 无记录返回 `{"items":[],"total":0}`，不返回 404。
- 客户身份一律取自 token，接口**不接受任何 customerId 入参**。

## 三、鉴权模型

- 独立拦截器 `CustomerAuthInterceptor`，覆盖 `/api/customer/**`，放行 `register` 与 `login`。
- 通过后写入 request attribute `authenticatedCustomer`，Controller 直接取用，不解析请求头。
- 客户 token 存 `customers.token`，**与 `sellers` 表完全隔离**：
  - 卖家 token 访问 `/api/customer/**` → 401
  - 客户 token 访问 `/api/seller/**` → 401
- 与卖家同口径：随机盐 + SHA-256、恒定时间比较、5 次失败锁 5 分钟、token 2 小时过期。

## 四、数据模型（本域自有，两张表）

**customers**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键 |
| `username` | VARCHAR(64) | 唯一索引，应用层忽略大小写判重 |
| `password_hash` | VARCHAR | 形如 `salt:hash` |
| `salt` | VARCHAR(64) | Base64 随机盐 |
| `phone` | VARCHAR(20) | 必填、**非唯一** |
| `default_trade_place` | VARCHAR(200) | 选填，纯文本 |
| `token` / `token_expires_at` | VARCHAR(64) / TIMESTAMP | 单值 token，2 小时 |
| `failed_attempts` / `locked_until` | INT / TIMESTAMP | 锁定策略 |
| `created_at` | TIMESTAMP | 注册时间 |

**customer_order_links**（客户 ↔ 意向关联）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键 |
| `customer_id` | BIGINT | 下单客户，索引 `(customer_id, submitted_at)` |
| `intent_id` | BIGINT | 对应 `intents.id`，唯一约束 |
| `product_id` | BIGINT | 冗余下单商品，避免联表缺失时排序失真 |
| `submitted_at` | TIMESTAMP | 冗余提交时间，用于列表排序 |
| `result_at` | TIMESTAMP | 交易时间；首次查询到终态时补齐并固定 |
| `created_at` | TIMESTAMP | 关联建立时间 |

> `intents` 表**没有任何改动**。

## 五、与意向域的关系（零修改）

| 交互 | 方式 |
|---|---|
| 下单 | 调用已有 `IntentService.submit(SubmitIntentRequest)`，不改其签名与实现 |
| 找回落库记录 | 调用已有 `IntentRepository.findByCodeHash(...)` + `IntentCodeGenerator.hash(...)` |
| 读状态 | 调用已有 `IntentRepository.findAllById(...)`，状态以 `intents.status` 为唯一事实来源 |
| 归属关系 | 写入本域 `customer_order_links`，不往 `intents` 加列 |

**代价**：`result_at` 无法从意向表拿到精确值，改为「首次观察到终态时从商品侧补齐」——成功取 `products.closedAt`，失败取 `products.lastTradeFailedAt`，补齐后落库不再变化。若后续意向域愿意加 `result_at` 列，本模块可平滑切换。
