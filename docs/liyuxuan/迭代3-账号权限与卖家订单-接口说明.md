## 三、接口详情

### 1. GET /api/seller/orders
- 请求头：`X-Token`
- 查询参数：`status`（选填，`PENDING`/`CONFIRMED`/`PACKED`/`SHIPPED`/`COMPLETED`/`CANCELLED`，忽略大小写；
  也接受订单域枚举名 `CUSTOMER_SUBMITTED`/`SELLER_CONFIRMED`/`READY_TO_SHIP`，由 `OrderStatusCodes.normalize` 归一）、`page`（缺省 1）、`size`（缺省 10，1～100）
- 成功 200：
```json
{
  "code": 200, "message": "success",
  "data": {
    "page": 1, "size": 10, "total": 3,
    "items": [{
      "orderNo": "SO202611150001",
      "customerId": 7, "customerName": "张三", "customerPhone": "13800000001",
      "status": "PENDING", "statusText": "客户下单",
      "totalAmount": 118.00, "itemCount": 1,
      "createdAt": "2026-11-15T02:00:00Z", "updatedAt": "2026-11-15T02:00:00Z",
      "allowedActions": ["CONFIRM"],
      "cancelReason": null,
      "items": [
        { "productId": 1, "productName": "《软件工程》", "coverImage": "/uploads/book.png",
          "unitPrice": 59.00, "quantity": 2, "subtotal": 118.00, "available": true }
      ]
    }]
  }
}
```
- 规则：
  - `allowedActions` 是**当前状态允许的推进动作**，前端据此显隐 4 个推进按钮，不自行判断状态，避免前后端口径漂移；
  - 终态（`COMPLETED` / `CANCELLED`）的 `allowedActions` 为空数组；
  - `statusText` 由本域统一补齐中文，前端不再维护状态文案映射表；
  - `itemCount` 是**明细行数（商品种数）**，不是件数——前端文案为「共 N 种商品」；
  - `items[].available` 为 `Boolean`：`false` 表示当前不可售（前端标注「无货」），`null` 表示订单域未表态，前端不标注。
- 失败 400：状态取值不在白名单（提示可选值）、`page < 1`、`size` 超出 1～100。

### 2. POST /api/seller/orders/{orderNo}/advance
- 入参：`{ "action": "CONFIRM" }`（只有动作码；状态变更的操作人与时间由订单域记录）
- `action` 取值（忽略大小写）：

| action | 含义 | 允许的当前状态 | 目标状态 |
|---|---|---|---|
| `CONFIRM` | 商家确认 | `PENDING` | `CONFIRMED` |
| `PACK` | 备货完成 | `CONFIRMED` | `PACKED` |
| `SHIP` | 开始发货 | `PACKED` | `SHIPPED` |
| `COMPLETE` | 交易完成 | `SHIPPED` | `COMPLETED` |

- 成功 200：`{ "code":200, "message":"订单状态已更新", "data": <OrderView> }`
- 失败 400：`action` 为空或不在上表（取消请调用 `/cancel`）
- 失败 404：订单号不存在
- 失败 409：跳级、回退、对已取消/已完成订单操作（**校验方为订单域**）

### 3. POST /api/seller/orders/{orderNo}/cancel
- 入参：`{ "reason": "选填，≤100 字" }`，请求体可整体省略
- 成功 200：`data` 为取消后的 `OrderView`，`status=CANCELLED`，`cancelReason` 省略请求体时为「卖家取消」
- 失败 409：订单已完成或已取消

### 4. GET /api/orders
- 请求头：`X-Token`（买家 token；卖家 token 无效）
- 查询参数：`page`、`size`，同上
- 成功 200：结构与卖家列表一致，`total` 为**本人**订单总数
- 失败 401：未登录 / token 过期
- 规则：`customerId` **只取自 token**，接口不接受任何 customerId 入参

### 5. POST /api/orders/{orderNo}/cancel
- 请求头：`X-Token`，入参 `{ "reason": "选填" }`
- 成功 200：`status=CANCELLED`
- 失败 404：订单不存在**或不属于当前客户**（不泄露订单是否存在）
- 失败 403：上游返回的订单归属与当前客户不一致（本域二次核对拦截，属防御性兜底）
- 失败 409：已发货 / 已完成 / 已取消（B.1.2：开始发货前才可取消）

## 四、与订单核心域的集成契约（OrderGateway）

订单的五态状态机、订单号生成、价格快照、库存锁定与释放在**订单核心域**（周琳皓）。
本域通过 `com.group7.shop.order.OrderGateway` 调用，接口方法：

| 方法 | 用途 |
|---|---|
| `PageResult<OrderView> sellerOrders(String status, int page, int size)` | 卖家列表 |
| `PageResult<OrderView> buyerOrders(Long customerId, int page, int size)` | 买家列表（必须按 customerId 过滤） |
| `OrderView advance(String orderNo, OrderAction action)` | 状态推进 |
| `OrderView cancelBySeller(String orderNo, String reason)` | 卖家取消 |
| `OrderView cancelByBuyer(Long customerId, String orderNo, String reason)` | 买家取消（原因已归一，由实现方落库） |

实现方需保证的错误语义：订单不存在 → 404；他人订单 → **同样 404**；状态机非法 → 409；取消时释放库存由实现方在同一事务内完成。

**接入方式**：订单域把实现类注册为 Bean 即可（`implements OrderGateway`），本域无需改动。
未注册时应用照常启动，订单接口返回 503「订单核心域尚未接入」，不影响前端与部署联调。

## 五、账号隔离规范（全组统一口径）

1. **身份只从 token 取**：`customerId` 一律来自拦截器写入的 request attribute `authenticatedCustomer`，任何接口都不接受请求体/URL 中的 customerId。
2. **路径即保护**：`/api/customer/**`、`/api/favorites/**`、`/api/cart/**`、`/api/orders/**` 已在 `CustomerAuthWebConfig` 登记，新增子路径无需再写鉴权代码；未登录一律 401。
3. **写操作二次核对**：对单条记录（订单、购物车条目、收藏）的删除/取消/修改，除按 customerId 过滤外，还要用 `AccountGuard.requireOwner(...)` 核对归属，越权返回 403。
4. **查不到就 404**：不要用 403 表达「记录不存在」，否则订单号/条目 id 可被枚举。

## 六、错误码汇总

| HTTP | 场景 |
|---|---|
| 400 | 参数不合法：状态白名单外、分页越界、动作码非法、取消原因超长 |
| 401 | 未登录、token 无效或过期（拦截器统一返回） |
| 403 | 操作他人资源（账号隔离二次核对） |
| 404 | 订单不存在或不属于当前客户 |
| 409 | 状态机不允许的推进 / 取消 |
| 503 | 订单核心域尚未接入（订单域合并前） |
