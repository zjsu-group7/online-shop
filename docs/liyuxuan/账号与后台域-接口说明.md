## 一、鉴权机制

- 卖家登录成功后服务端生成随机 `token`（2 个 UUID 拼接，64 位十六进制），仅保存在 `sellers.token` 字段（**不做服务端会话**）。
- 除 `POST /api/seller/login` 外，所有 `/api/seller/**` 由 `SellerAuthInterceptor` 拦截，校验请求头 `X-Token`。
- `X-Token` 缺失或无效 → 返回 HTTP 401，响应体 `{"code":401,"message":"未登录或登录已失效","data":null}`（与全局异常处理同格式）。
- 校验通过后将当前 `Seller` 写入 request attribute `authenticatedSeller`，Controller 直接取用，**不自行解析 token**。
- **重新登录使旧 token 失效**（覆盖为新 token）；退出登录 / 修改密码成功后 token 置空，旧 token 即失效。

## 二、接口清单（本域 4 个）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/seller/login` | 否 | 登录，返回 token |
| POST | `/api/seller/logout` | token | 退出，token 失效 |
| POST | `/api/seller/password` | token | 修改密码（校验原密码，改后旧 token 失效） |
| GET  | `/api/seller/overview` | token | 后台首页：在售商品 + 意向购买人列表（按提交时间正序） |

## 三、接口详情

### 1. POST /api/seller/login
- 入参：`{ "username": "seller", "password": "12345678" }`（均必填，`@NotBlank`）
- 成功 200：`{ "code":200, "message":"登录成功", "data": { "token": "…64位…", "username": "seller" } }`
- 失败 401：`{ "code":401, "message":"用户名或密码错误", "data":null }`
- 规则：用户名不存在与密码不匹配**返回同一提示**，避免账号枚举；**重新登录使旧 token 失效**。

### 2. POST /api/seller/logout
- 请求头：`X-Token: <token>`
- 成功 200：`{ "code":200, "message":"已退出登录", "data":null }`
- 规则：将当前账号 `token` 置空；之后该 token 访问任意 `/api/seller/**` 返回 401。

### 3. POST /api/seller/password
- 请求头：`X-Token: <token>`
- 入参：`{ "oldPassword": "12345678", "newPassword": "newpass123" }`
- 成功 200：`{ "code":200, "message":"密码修改成功，请重新登录", "data":null }`
- 失败 400（原密码错误）：`{ "code":400, "message":"原密码错误", "data":null }`
- 失败 400（新密码 < 8 位）：`{ "code":400, "message":"新密码不少于8位", "data":null }`
- 规则：**先校验原密码，再校验新密码长度**；通过后换盐重算哈希（SHA-256 + 随机盐，存储为 `salt:hash`）→ **token 置空，旧 token 失效，需重新登录**。
- 边界：校验失败时不写库，**不影响当前 token**（可继续操作）。

### 4. GET /api/seller/overview
- 请求头：`X-Token: <token>`
- 成功 200 出参：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "product": { "id": 1, "name": "示例商品", "price": 9.99, "status": "ON_SALE", "imageUrl": "/uploads/xxx.png", "createdAt": "2026-10-11T10:00:00Z" },
    "queue": [
      { "id": 10, "name": "张三", "phone": "13800000001", "status": "WAITING", "position": 1, "submittedAt": "2026-10-11T10:05:00Z" },
      { "id": 11, "name": "李四", "phone": "13800000002", "status": "IN_TRADE", "position": null, "submittedAt": "2026-10-11T10:06:00Z" }
    ],
    "canPublish": false
  }
}
```
- 规则：
  - `product`：当前在售/交易中（`ON_SALE` / `FROZEN`）商品，取最近创建的一件，无则 `null`。
  - `queue`：该商品意向购买人列表，**按 `submittedAt` 正序**；**仅含 `WAITING` 与 `IN_TRADE`**（`TRADED` / `FAILED` / `CANCELLED` 为终态，不入队）；`position` 为排队位次（仅 `WAITING` 递增计数，`IN_TRADE` 置 `null`）；**不含口令码 `codeHash`**。
  - `canPublish`：当前无在售/交易中商品时为 `true`，否则 `false`（同一时间仅一件在售）。

## 四、数据模型（本域）

**Seller**：`id, username(unique), passwordHash(格式 salt:hash), salt, token`

**Intent**（冻结数据模型，供 overview 只读聚合；写侧由意向域华天遥实现）：
`id, productId, name, phone, codeHash, status(WAITING/IN_TRADE/TRADED/FAILED/CANCELLED), submittedAt, version`

## 五、账号自动初始化

- 应用启动时 `SellerAccountInitializer`（`CommandLineRunner`）检查卖家表：`count == 0` 才创建，**幂等**，重启不重复创建。
- 默认凭据来自配置，可在 `application.yml` 覆盖：

```yaml
app:
  default-seller:
    username: seller
    password: "12345678"
```

- 创建时把用户名与密码打印到启动日志，方便演示与验收取用。

## 六、运行与配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `server.port` | `8080` | 团队约定端口；若被占用（如 VMware NAT 的 vmnat.exe）可 `--server.port=8081` 覆盖 |
| `spring.datasource.url` | `jdbc:h2:file:./data/onlineshop` | H2 文件库，重启保留 |
| `app.upload-dir` | `./uploads` | 商品图片落盘目录，经 `/uploads/**` 暴露 |
| `spring.h2.console.path` | `/h2-console` | 便于验收时查看建表结果 |

启动与自测：

```bash
mvn clean package
java -jar target/online-shop-0.0.1-SNAPSHOT.jar
# 登录拿 token
curl -X POST http://localhost:8080/api/seller/login \
  -H "Content-Type: application/json" \
  -d '{"username":"seller","password":"12345678"}'
# 带 token 打开后台首页数据
curl http://localhost:8080/api/seller/overview -H "X-Token: <token>"
```

## 七、与他人的集成边界

- `ProductService` / `ProductRepository`（李婉婷，商品域）供 overview 读取在售商品；本域**不修改**商品写逻辑。
- `Intent` 实体与 `IntentRepository`（只读）供 overview 聚合意向队列；**意向的提交/查询/修改/撤销由华天遥实现**，本域不改动其写逻辑。
- `SellerProductController`（李婉婷）下的 `/api/seller/products*`、`/api/seller/history` 等均已被**同一拦截器统一保护**，无需各自重复鉴权。
- 交易域（周琳皓）的 `deal` / `result` 会改变商品与意向状态，overview 因此**动态反映**当前商品与队列（前端每 8 秒轮询）。
