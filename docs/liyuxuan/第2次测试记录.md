## 三、尚未解决的问题

| 编号 | 问题 | 说明 / 处置 |
|------|------|-------------|
| U-1 | ~~`SellerAuthTest` 暂无法自动运行~~ | **已解决**：仓库补齐 `@SpringBootApplication` 主类与 `application.yml` 后，`mvn test` 12/12 通过。 |
| U-2 | `PasswordHasher.matches` 初版缺陷 | 已修复（先解码再做恒定时间比较），并纳入回归用例。 |
| U-3 | 意向队列只能造数据验证 | 意向域的 `POST /api/intents`（华天遥）尚未落地，端到端无法真实造意向；overview 的队列/位次/过滤逻辑已由集成测试直接写库验证。**待意向域接口就绪后补一次真实链路联调。** |
| U-4 | 团队技术栈版本口径不一 | 《技术选型》《Java实现进度》写 Spring Boot 3.3，实际 `pom.xml` 为 **Spring Boot 4.0.8**（含 Jackson 3、测试包名迁移）。**本域代码已按 4.0.8 适配并验证通过**，建议组长统一口径。 |
| U-5 | ~~默认端口与文档不一致~~ | **已统一**：默认端口改回 **8080**，与《构建与部署手册》《接口设计》一致；本机 8080 被 VMware NAT（`vmnat.exe`）占用，本轮端到端验证以 `--server.port=8081` 覆盖执行，不影响结论。 |
| U-6 | 密码哈希算法与选型建议不同 | 选型建议 BCrypt，实为 JDK 内置 SHA-256 + 随机盐（16 字节，`salt:hash` 存储、恒定时间比较），以避免为引入 `spring-security-crypto` 改动他人 `pom.xml`。接口与存储字段不受影响，可平滑替换。 |
